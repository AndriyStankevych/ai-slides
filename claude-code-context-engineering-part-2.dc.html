Push the Work Off the Window

A SCRIPT IT RUNS
The code never arrives
Only its output does. A validation routine or a data transform in scripts/ costs nothing but the lines it prints — and it runs the same way every time.
A FILE IT LINKS
Detail on demand
"Read checklist.md at the review step." The checklist stays on disk until that step happens, and the body stays short enough to follow.
A FORK IT RUNS IN
Noise in another window
context: fork inherits the conversation, does the thirty reads elsewhere, and hands back the result.
A FENCE AROUND IT
Narrow on purpose
allowed-tools with no Edit and no Write means a reviewing skill cannot be talked into rewriting.

Same shape as everything else: the index stays resident, the detail stays retrievable, and the transcript stays out.

Deny, Then Ask, Then Allow

deny
→
ask
→
allow
first match wins — specificity does not enter into it
"deny": ["Bash(az *)"] "allow": ["Bash(az account show)"]
The allow never fires — and the same holds between ask and allow.
Bash  bare name in deny removes the tool from context — Claude never sees it Bash(dotnet nuget *)  scoped deny leaves the tool and blocks the matching calls
WHERE THE STAR GOES
Bash(dotnet build *)only dotnet build, bare included
Bash(dotnet *)every subcommand, nuget push too
Bash(az *)the space matters — Bash(az*) catches azcopy
Compound commands: every subcommand must match an allow on its own. Deny and ask fire if any subcommand matches, subshells included.
ENFORCED, NOT REQUESTED
applied by Claude Code, not by the model — unlike anything in CLAUDE.md
DENY WINS FROM ANY SCOPE
a user deny blocks a project allow; no flag overrides a managed deny
NOT A SECURITY BOUNDARY
Bash(az *) stops az group delete, not /usr/bin/az or sh -c

Prompt cacheMECHANICS · 09

One Prefix, Three Layers

The API matches the start of each request against what it just processed and reuses it. The match is exact: there is no per-file cache, so a change anywhere invalidates everything after it.

WHAT IS IN IT
CHANGES WHEN
System prompt
core instructions, tool definitions
the set of loaded tool definitions changes
Project context
CLAUDE.md, auto memory, unscoped rules
the session starts, or after /clear or /compact
Conversation
your messages, replies, tool results
every turn — and it appends at the bottom

A change in the conversation layer leaves the two above it cached, read at roughly a tenth of the input price. A change in the system prompt reprocesses the lot.

WHY CLAUDE.MD WAITS
it is read once at startup and held; a mid-session edit neither breaks the cache nor applies until /clear
ONE MACHINE, ONE DIRECTORY
the working directory and platform are in the prompt, so worktrees of one repo do not share a cache
FORK READS, SUB-AGENT DOESN'T
a fork inherits your prefix and hits your cache; a sub-agent builds its own from scratch

What Breaks It, What Doesn't

REBUILDS THE PREFIX
/model — each model has its own cache, identical content or not /effort — on most models, its own cache too turning on fast mode — once per conversation an MCP server connecting or dropping, when its tools sit in the prefix a plugin that brings MCP servers, enabled or disabled denying a whole tool: a bare Bash or WebFetch deny /compact — by design; the history it replaces was the prefix upgrading Claude Code — new prompt, new tools
KEEPS IT — STOP AVOIDING THESE
editing files in the repo — reads append, they do not rewrite history editing CLAUDE.md — and it will not apply until /clear changing permission mode or output style, plan mode included invoking a skill or a command — it arrives as a message /recap — it appends a summary instead of replacing history /rewind — it truncates back to a prefix that is already warm spawning a sub-agent — its window is separate, yours is untouched scoped deny rules, and every allow and ask rule
DECIDE AT THE TOP
pick model and effort when the session starts; mid-task switching is where the cost lands
COMPACT ON PURPOSE
at a task boundary, not mid-task; abandoning a path is /rewind, not /compact
READ THE RATIO
/usage reports hit ratio, misses, whether the cache is warm — often the cause of the last miss

/doctorPRACTICE · 16

Configuration Fails Quietly

Nothing in this deck throws an exception when you get it wrong. It just stops happening, and you conclude the model ignored you.

A RULE WITH A TYPO
a tool name that matches nothing — the rule loads and guards nothing
A RULE ON THE WRONG TOOL
a path rule on Write or Glob is accepted and never consulted
FRONTMATTER THAT WON'T PARSE
the skill is simply never offered, and nothing tells you so
/doctor makes it visible. It checks the install and reports the configuration it actually resolved — including what it rejected.
AFTER YOU CHANGE THINGS
run it when you edit settings, add a plugin or write a skill — not the next time something feels off
BEFORE YOU BLAME THE MODEL
when a rule you are sure you wrote is not being applied, check that it parsed
THE PAIR TO REMEMBER
/context shows what is in the window; /doctor shows what your configuration resolved to
